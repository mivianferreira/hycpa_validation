About HyCPA

HyCPA is a tool for analyzing the impact of change propagation in object-oriented software systems. The results presented in this tool were generated by a model developed in a PhD dissertation that considers the software system's change history and its dependence analysis (Ferreira, 2026). The concepts used in this tool are described below.

Concepts

Change propagation

A change in a given class of an object-oriented software system may trigger changes in other classes, which may in turn trigger further changes. This effect is called change propagation. Manual evaluation of change propagation can be infeasible. Ferreira's PhD dissertation introduces a model for analyzing the propagation of change in object-oriented systems.

Hybrid Change Propagation Analysis

The model developed in Ferreira's PhD dissertation considers both the change history, which records past modifications to the software, and the dependence analysis, which examines how different parts of the software rely on each other. This is why it is called "hybrid".

Class (source)

The class whose change impacts the developer needs to be analyzed.

Deterministic impact

The deterministic impact is the number of classes a change in a given class may impact. It is calculated by a depth search algorithm in Ferreira's model.

Probabilistic impact

The probabilistic impact is the number of classes a change in a given class may impact. It is calculated by a probabilistic algorithm in Ferreira's model.

Health score

The health score of a class is a metric generated by Ferreira's model that indicates how well-constructed a class is. This metric ranges from 0 to 1; the higher the health score, the better the class design.

Community

A community is a group of classes whose changes interact with one another. A class may belong to more than one community. The more communities a class is involved in, the greater its impact on the system. The tool shows, for each class, the communities it belongs to, along with the classes within each community.

Impact Probability (Prob)

It is the probability that a change in a given class A (source) will cause a change in a class X (target). The impact probability lies in the range (0, 1). The tool uses the following colors to indicate impact probability:

ColourMeaning
RedProb ≥ 0.5
OrangeProb ≥ 0.3
GreenOtherwise

Rank

Ferreira's model ranks the classes impacted by a change in class A (source) according to the impact probability (Prob) of each impacted class (target).

Propagation path

A propagation path includes the source class (under analysis) and the target class (impacted) involved in change propagation. For example, in A → B → C → D, a change in A may reach D: A impacts B, B impacts C, and C impacts D.

Distance

The distance of a propagation path is defined as the number of edges between the class under analysis and the impacted class; for example, in the path A → B → C → D, the distance is 3.

Data shown for each propagation path

The change propagation path diagram

The tool shows change propagation as a directed graph, where a circle represents a class and an edge from A to B indicates that a change in A may propagate to B.

In the diagram, the yellow circle represents the class under analysis (source), the green circle represents the impacted class (target), and the blank circles represent the classes through which the change will propagate until it reaches the target class.

For each class, its health score is shown.

For each edge, the tool shows the co-change quantity and/or the coupling types involved between the classes. In Ferreira's model, the co-change quantity is based on the software system's change history, and coupling types are identified by analyzing its structural dependencies. Those concepts are described as follows.

  • Co-change: A co-change is the event of changing a class in the same change activity. In the change propagation path, when an edge from class X to class Y corresponds to a co-change between X and Y, the tool shows the number of times that co-change occurred between the classes.
  • Coupling types: In a software system, a class may be linked to other classes in several ways, such as method calls, inheritance, attribute use, etc. In the change propagation path, when an edge from class X to class Y represents a structural dependency of X on Y, the tool lists the types of coupling involved in this dependency.

How to use this tool to give feedback to the author

You can provide feedback in the General Analysis text box:

  • Tell us how important you consider this type of tool or model for software change tasks.
  • Tell us how consistent you think the results presented by the tool are, both by the deterministic and the probabilistic results.
  • Tell us which metric you think seems to be more appropriate to rank the most impactful classes in the system: Deterministic Targets (Det), Probabilistic Targets (Prob), Health, or number of communities.
  • Tell us how consistent you think the list of classes per community is.
  • We will appreciate your suggestions to improve the presentation of the results.

You can also vote ✅ Correct / ❌ Incorrect / ❓ Unsure and leave a comment for each result presented by the tool. Hitting Submit posts the response to FormSubmit (change.vein@gmail.com) and caches it in localStorage for offline recovery (by the author). The Submit All button and a CSV export of the per-class analyses you entered are also available.
