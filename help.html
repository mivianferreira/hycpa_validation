How to read this site

Reference for the HyCPA change-propagation validation site.

Concepts

Class (source / seed)

The class being modified. Each class is analysed independently; its code smell score (0..1) summarises how many CK metrics fall in the "bad" zone (per Aniche et al. thresholds; primary metrics CBO/WMC/RFC/LCOM/DIT/NOC weighted 2×).

Communities

Propagation is restricted to the union of link-communities (Ahn et al., 2010) the seed belongs to. Showing them helps reason about the scope.

Edge probability

Each arc u → v carries a Noisy-OR (Pearl, 1988) of three signals:

  • S — structural coupling strength (Noisy-OR over typed couplings from CK / Briand et al.)
  • L — logical / evolutionary co-change (Gall et al.; D'Ambros et al.)
  • F — target code smell score (CK metrics in bad zone; Aniche et al. thresholds)

p(u→v) = 1 − (1 − α·S)(1 − β·L)(1 − γ·F)

Two cascades

Deterministic

BFS within the source class's communities; an arc fires when p(u→v) ≥ θ. Reproducible and yields a single explanatory path (via_id chain) per target.

Monte Carlo

Independent-Cascade (Kempe, Kleinberg & Tardos, 2003) with mc_runs simulations. Each target gets an empirical probability and an average distance (in edges) across runs. We list only entries with prob ≥ mc_threshold. No causal path is recorded.

Parameters in the header

  • α, β, γ — weights on S, L, F (recommended α+β+γ ≈ 1.0)
  • θ — deterministic firing threshold
  • combine — how multiple coupling types on a single arc are aggregated (noisy_or / max / sum)
  • mc_runs — number of Monte-Carlo simulations
  • mc_threshold — minimum empirical probability surfaced

Per-card fields

  • Rank — position in the ranked list of targets for the current tab.
  • Prob — propagation probability (0..1). Coloured red ≥ 0.5, orange ≥ 0.3, green otherwise.
  • Distance — number of edges from the source class to the target (deterministic) or Avg Distance across MC runs.
  • Health — 1 − code smell score for the target class (CK-derived).
  • Path diagram — only meaningful in the Deterministic tab; reconstructed by chaining via_id back to the source class. Each edge tag shows co-change weight and detected coupling types (when present in featured_graph).

Validation flow

For each target, vote Correct / Incorrect / Unsure and (optionally) leave a comment. Hitting Submit posts the response to FormSubmit (change.vein@gmail.com) and caches it in localStorage for offline recovery. The repo page also has a Submit All button and a CSV export of the per-class analyses you entered.
